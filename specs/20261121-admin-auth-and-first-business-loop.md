# 管理员认证与首个业务阶段规格

## 决策状态

已由用户确认，作为认证与首个实现阶段的当前规格。本文取代产品方向稿中与管理员初始化、登录、用户/角色、API Key、Skills 可见性及当前阶段范围冲突的旧条款；旧条款摘要保留在文末修订记录中。

## 首个实现阶段

实现本地登录、管理员初始化与恢复、用户管理、角色管理、API Key 管理及授权过滤。数据库预置少量 demo MCP 服务/工具和 Skills 条目，用于验证授权关系和列表过滤。demo 条目不连接下游，不提供工具调用，也不代表已实现 MCP 服务管理或 Skills 广场。

提供一个只读 Bearer API，用 API Key 识别用户并返回该用户获准查看的 demo 服务、工具和 Skills 条目；该 API 不执行工具。真实 MCP 下游连接与调用、服务目录管理、Skills 广场接入和 GitHub 导入属于后续阶段。

## 管理员初始化与恢复

- 空数据库首次启动时，从 `.env` 或环境变量读取管理员账号和密码，创建用户并绑定固定的管理员角色。
- 首次初始化缺少管理员账号或密码时，服务拒绝启动。
- 管理员已存在后，环境变量只作为历史初始化配置，不覆盖数据库中的账号或密码；已有数据库启动不再要求这些变量。
- 管理员忘记密码时，通过服务器本机 CLI 重置数据库中的密码。普通用户密码由管理员在控制台重置。
- 首版只允许初始化的单一账号持有固定管理员角色；管理员不能从控制台创建或提升另一位管理员。

## 登录与用户

- 所有账号使用账号和密码登录网页。网页会话固定有效 12 小时，不提供“记住我”。
- 管理员创建普通用户时，系统生成随机初始密码并仅在创建完成时展示一次；不强制首次登录改密。
- 用户可自行修改密码，修改时必须验证当前密码。管理员也可重置普通用户密码。
- 用户自行修改密码或管理员重置密码后，立即注销该用户的所有网页会话；API Key 不受密码变更影响。
- 管理员可以停用和重新启用普通用户。停用立即禁止密码登录并使该用户全部 API Key 永久失效；重新启用不会恢复旧 Key，用户需重新创建 Key。
- 普通用户不能创建用户或执行平台管理操作。

## 角色与资源授权

- 系统有一个固定管理员角色，绑定到环境变量初始化的管理员账号。管理员拥有全部菜单、MCP 服务/工具及特殊 Skills 的访问权。
- 管理员可创建普通角色。普通角色不能获得用户或平台管理权限，也不单独配置菜单权限。
- 普通用户至少持有一个普通角色，可以持有多个；其资源权限取各角色授权的并集。
- 普通角色可获准查看 MCP 服务、MCP 工具和特殊 agent-plugin/Skills 条目。MCP/工具授权同时决定可见性和调用授权，未授权默认拒绝。即使当前阶段没有真实工具调用，Bearer 只读 API 也必须按相同授权过滤服务和工具条目。
- 公共 Skills 对所有人可见；特殊 Skills 需要登录且用户持有被授权角色。管理员角色绕过特殊 Skills 的普通角色过滤。
- 角色权限变更立即影响已有 API Key 的请求。角色仍分配给用户时不得删除；应先移除所有关联。

## API Key

- API Key 只用于 MCP Bearer 鉴权，不用于网页登录。网页使用账号密码认证。
- 每个用户可拥有多个具名 Key。创建 Key 时必须明确选择过期时间或永久有效，不预选默认值。
- 用户可创建、查看/复制、列出和吊销自己的 Key；管理员可管理所有用户的 Key。创建者和目标用户/管理员可再次复制已有 Key 明文。
- Key 明文直接保存在 SQLite，供用户本人和管理员再次复制。SQLite 数据库文件及其备份因此包含所有有效 Key；任何能读取这些文件的人都能取得其中的凭证。
- 用户停用时，已有 Key 永久失效；恢复账号后用户可创建新的 Key。
- Key 认证后按所属用户当前角色计算资源权限；角色或角色授权变更立即生效，无需重新创建 Key。

## SQLite 决策

首个实现阶段仅使用 SQLite，不实现或测试 PostgreSQL dialect。数据库访问继续通过 Kysely 边界组织，避免无必要地将领域逻辑耦合到 SQLite；这不代表 PostgreSQL 已受支持。PostgreSQL 是否引入、迁移与测试范围将在后续单独决策。

## 取代的旧决定

以下旧条款保留在历史产品方向稿中，但不再适用于本规格范围；当前行为以本文为准：

- “每位用户恰好分配一个管理员自定义角色”改为普通用户可分配多个普通角色并取权限并集，另有固定管理员角色。
- “平台管理员是一种独立的平台管理权限，不由 MCP 服务角色隐式授予”改为首版使用固定管理员角色；该角色仅绑定初始化账号，并自动拥有全部菜单、MCP/工具和特殊 Skills 权限。
- “普通用户不能创建、查看、轮换或吊销 Key”改为用户管理自己的 Key，管理员可管理所有 Key。
- “Key 同时用于网页工作台和 MCP Bearer 鉴权”改为网页使用账号密码，Key 仅用于 Bearer 鉴权。
- “新 Key 创建时明文只显示一次；旧值不可回显”改为 Key 明文存入 SQLite，用户本人和管理员可重复复制。
- “Skills 可见性不受 MCP 角色控制”改为公共 Skills 公开可见，特殊 Skills 按登录状态和角色过滤，管理员可见全部。
- 首个实现阶段不接真实 MCP 下游、不提供 Skills 广场集成或目录管理；使用少量 demo 资源验证授权过滤。
