## 页面与流程

- 一级菜单只保留「MCP 服务」，移除独立「REST 导入」；调用审计、访问控制保持当前入口。
- 服务列表统一展示所有服务，接入方式明确显示「原生 MCP」或「REST API」。
- 「接入服务」先选择接入方式。原生 MCP 填写连接配置；REST API 再选择手工定义、OpenAPI 或 cURL。
- 手工接入先保存服务，再在其工具目录定义 REST 工具；文档导入保持输入、预览编辑、勾选和确认的过程。
- 新建或导入成功后回到统一服务页面，展示相应服务与工具，提供试调用和后续配置；多目标导入展示保存结果，允许查看任一服务。
- 既有 REST 服务详情提供「导入工具」，可选择 OpenAPI 或 cURL；匹配当前目标时预选更新当前服务，其他目标仍按既有分组规则处理。新建及重导入都保留预览确认。
- 配置、启停、工具目录和试调用在同一服务详情管理；原生 MCP 显示测试连接及同步，REST 显示定义及导入操作。
- 页面继续使用现有 Swiss editorial 的颜色、边框、间距、排版和按钮样式，必要的新接入选择组件复用现有设计变量。

## 行为边界

一个服务对应一种接入方式，登记后不能互换。后端 `kind`、HTTP/MCP 协议、数据库、执行、授权与审计规则保持现有行为。原生 MCP 使用实际连接状态；REST 使用「配置有效」，不显示为已连接。
