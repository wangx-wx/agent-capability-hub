# MCP 与 REST 接入实施记录

## 依据与分支

依据 [接入规格](20261122-mcp-rest-integration.md)和 [TDD 测试边界](20261122-mcp-tdd-boundaries.md)，于 2026-11-22 开始实施。用户明确要求继续使用 `dev_mcp_research_261121`。完成前不合入 main，不推送远端。

## 已实现切片

### 1. 官方 SDK 的现代上游发现

- 项目级安装并锁定 `@modelcontextprotocol/server`、`client`、`core` 2.4.0 和独立发布的 `node` 2.1.2。pnpm 使用既有共享缓存，依赖登记在 `apps/api/package.json` 与根锁文件中。
- 新增 `/mcp`，按每次请求验证当前平台 API Key、用户启用状态、过期和吊销状态。
- 使用官方 `createMcpHandler` 与 Node 适配器，复用 Express 已解析的请求体。
- 官方低层 `Server` 仅声明 tools；避免高层服务器自动声明尚未实现的 `listChanged` 通知能力。
- 空目录不公开 demo 占位工具。工具登记、执行和审计仍待后续切片。
- 失败测试：锁定现代协议的真实 SDK 客户端不能通过尚不存在的 `/mcp` 协商。
- 实现后验证：真实 TCP 连接协商为 `2026-07-28`，capabilities 为 `{tools: {}}`，tools/list 返回空目录。API 回归和前后端类型检查通过。

### 2. 部署配置的 Origin 校验

- `/mcp` 使用官方 Node `originValidation`；无 Origin 请求正常处理。
- `MCP_ALLOWED_ORIGINS` 是逗号分隔的允许来源主机名，遵循 SDK 按 hostname 校验的语义；空值拒绝所有携带 Origin 的浏览器请求。
- 该校验不限制上下游目标 IP、网段或内公网访问。
- TDD：未允许来源原先得到成功响应；接入校验后 HTTP 403。现代 SDK 发现回归与前后端类型检查通过。

## 下一步

### 10. 手工 REST 定义与统一调用

- 服务登记支持 REST，`POST /api/admin/services/:id/tools` 保存管理员定义的操作；配置保存与发布不调用业务接口。
- 原生与 REST 复用稳定工具 ID、精确授权、MCP 出口及正式审计。内部 HTTP 映射与试调用示例不进入公开 tools/list 定义。
- 分组参数支持 path/header 标量、query 标量和 form 数组、JSON body；保留 server base path，独立编码路径值。静态凭证头最后注入，不能被参数覆盖。
- 成功根据 2xx；正文原样进入 MCP 文本结果，不加业务包装。初步采用逐块读取响应并校验字节预算，支持请求超时、不重发调用。
- 真实 HTTP 测试从 REST 类型不支持的 400 开始，验证 `%2F` 路径编码、重复 query、0／false、凭证覆盖、原样 JSON 文本及统一审计。API 回归和前后端类型检查通过。
- 示例默认值、其余响应类型、完整部署预算与导入仍在后续切片验证。

### 9. 旧 SSE 双通道凭证与原生结果

- 受控旧 SSE 服务实测 GET 流与 POST 消息均注入管理员静态凭证。
- 失败测试发现大小写不同的同名凭证头被 Headers 拼接；改用大小写无关的 set 覆盖，避免重复认证值。
- 图片 content 和 structuredContent 经旧下游到现代上游保持；关闭平台后 SSE 连接归零。
- 真实网络测试和类型检查通过；不提供上游旧 SSE 服务端出口。

### 8. 下游连接状态与自动退避恢复

- 失败测试复现现代 HTTP 网络失败后仍显示 connected；现将传输故障置为 disconnected，并独立退避重连。
- 恢复只重做发现协议协商，不重放工具调用，不应用工具目录变化。受控服务停机／同端口恢复测试验证新服务收到零次重发，旧已确认目录保持。
- 服务登记／重新启用及启动恢复时建立启用的下游连接；认证失败保留配置并标记 authentication_failed，不自动更换传输。
- 停用、删除与关闭清理恢复任务；已发调用仍按在途规则释放连接。
- 真实恢复测试、在途调用和 API 回归及类型检查通过。旧 SSE 通道与认证错误的专项测试仍待补充。

### 7. 停用后的在途调用与连接释放

- 失败测试复现停用时立即关闭下游连接导致已发调用返回 Connection closed。
- 下游 client 记录在途使用；停用或配置替换先移除可用连接，仍有调用时延迟到最后一个使用者完成后关闭。
- 停用立即隐藏工具、拒绝新调用；已发调用保留实际结果。真实双端 SDK 测试通过，改名／正式调用回归和类型检查通过。

### 6. 服务配置预览、命名空间改名与删除

- 管理 API 增加 `/:id/config-preview` POST、`/:id` PATCH/DELETE；保存前可查看每个工具的旧／新公开名。
- 改名更新正式工具名并保留内部 ID 与角色授权，不建立旧名别名，不改写审计快照。
- 删除服务先清理所属工具资源与授权，再删除服务配置；审计与累计统计保留。
- 真实 SDK 生命周期测试从配置预览的 404 开始，验证新名立即可用、旧名失败、授权 ID 保持、历史名称保留及删除后的累计数字。类型检查通过。
- 在途调用的连接延迟释放与自动恢复仍待单独切片验证，当前不宣称已完成该项。

### 5. 正式调用、精确授权与最小审计

- 上游 tools/call 路由到已确认工具；再次读取当前精确工具授权、服务启用与连接状态。
- schema 校验和调用位于前置审计之后；普通调用的成功和失败均记录，不保存参数或结果正文。
- 新增 `/api/admin/audit` 管理员明细与 `/api/usage` 自己的累计次数、成功数和失败数；审计不外键级联删除历史。
- 下游凭证独立注入，不转发平台 Key。普通调用默认 60 秒且不自行重发；关闭 SDK MRTR 自动补充与重试。
- 管理员试调用接口为 `/api/admin/services/:id/tools/:toolId/test`，不进入正式审计。
- 启动时将未结束记录标为未知；审计建立失败拒绝执行，后置更新失败独立写出不含正文的故障提示并返回实际结果。
- 真实 MCP 调用测试覆盖授权列表、成功调用、越权不发出、服务凭证与正式统计，以及试调用不增加统计。API 回归和类型检查通过。
- SQLite 故障、重启未知状态及超时／取消的专项验证在后续切片补充。

审计故障补充验证已通过：SQLite query-only 拒绝前置写入时下游零调用、累计零记录；SQLite trigger 仅拒绝审计更新时返回实际结果，下游一次执行、独立故障提示、统计仅总数增加。移除故障并执行启动初始化后，未结束记录变为 unknown，成功／失败数仍为零。所有结果通过公开 API 观察。

审计入口修正：失败测试发现，SDK 在执行器之前拒绝非对象 arguments 时原先没有记录。现将正式审计起点置于已认证 `/mcp` 入口，执行器完成正常终态；SDK 提前拒绝时入口补记失败。后置审计写入失败不会因入口收尾再次更新或重发业务调用。

### 4. 原生 MCP 分页发现、预览与确认发布

- 管理接口增加 `/:id/sync-preview`、`/:id/sync-confirm` 和 `/:id/tools`，均挂在 `/api/admin/services` 下。
- 官方 SDK `auto` 模式连接 HTTP 下游，SSE 采用 legacy 模式；静态凭证通过统一解析入口获取，保留调用者上下文参数供未来个人凭证来源扩展。
- 发现使用 SDK 聚合分页，并刷新发现缓存；确认前不发布工具。预览包含新增、修改和删除，绑定服务配置与目录快照。
- 确认同名工具时保留内部 ID 和角色授权；删除通过资源级级联清理工具与授权。新工具不添加普通角色授权。
- 上游读取已确认目录，按当前精确工具授权和启用／连接状态过滤，公开名使用 `namespace__originalName`。
- 受控双页 MCP 服务的真实网络测试从缺失接口的 404 开始，确认前为空、确认后完整公开两项工具。API 回归及类型检查通过。
- 自动重连、服务配置编辑、调用审计及 schema 预算仍待后续切片；本节仅记录已验证行为。

### 3. MCP 服务登记与持久配置

- 新增管理员会话保护的 `/api/admin/services` POST/GET 和 `/api/admin/services/:id` GET。
- 保存服务资源的稳定 ID、命名空间、HTTP/SSE 传输、静态请求头、超时和启用状态；配置落入 SQLite 的增量迁移。
- 名称自动建议命名空间，管理员可显式提供；重复命名空间拒绝保存。HTTP(S)、请求头、超时及配置结构按协议检查，不进行地址网段过滤。
- 登记不请求下游，不可达地址仍能保存；新 MCP 服务默认为停用、未连接，不公开占位工具。
- TDD：新增接口先返回 404；实现后登记和读取配置通过，API 回归及类型检查通过。

补充协议验证：官方 SDK legacy 模式协商为 `2025-11-25`，无上游 Session ID；连接使用的 Key 吊销后新 HTTP 请求立即返回 401。这两项由已接入的 SDK 与逐请求鉴权满足，无需新增另一套协议实现。

逐项验证旧版无状态兼容、Key 生命周期与 Origin；随后按依赖顺序接入持久目录、原生下游、授权和正式审计、REST 及导入与控制台。
