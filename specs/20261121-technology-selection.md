# Agent 能力中台技术选型与周期

## 决策状态

已确定首期技术方向。周期是基于当前产品规格的规划估算，技术验证结束后再细化为迭代计划。

## 技术选型

- **运行时与语言**：Node.js LTS、TypeScript。
- **后端**：Express，采用模块化单体；管理 API、用户工作台 API 和 MCP 网关在同一服务中按模块组织。
- **MCP**：官方 MCP TypeScript SDK。首周验证上游 Streamable HTTP、下游 Streamable HTTP 与旧版 SSE 的组合和会话生命周期。
- **数据库**：首期默认 SQLite；同时从首版支持 PostgreSQL。
- **数据库访问**：Kysely，按连接配置选择 SQLite 或 PostgreSQL dialect。业务逻辑通过统一的数据访问模块工作，不在业务模块中拼接数据库专属 SQL。
- **数据库可移植约束**：首期只使用两种数据库共同支持的字段和查询能力；避免 SQLite 专属类型、PG 专属 JSON 查询、方言函数和不兼容事务语义。ID 使用应用生成的 UUID 字符串，JSON schema 和其他结构化值按文本存储并在应用层解析，时间以 UTC ISO 8601 值统一处理。
- **迁移与验证**：迁移使用 Kysely migration API；CI 至少对 SQLite 和 PostgreSQL 各运行一次数据库集成测试，避免 PostgreSQL 支持只停留在设计层面。
- **前端**：React、TypeScript、Vite；管理控制台、用户工作台和公开 Skills 广场作为同一 Web 应用中的独立路由入口。
- **仓库与部署**：pnpm workspace；首期使用 Docker Compose 部署应用和可选 PostgreSQL。默认 SQLite 部署不要求额外数据库服务。
- **测试**：Vitest 单元与服务测试、双数据库集成测试、Playwright 端到端测试覆盖授权拒绝、API Key 展示、MCP 调用审计和 Skills 浏览等关键流程。

## SQLite 与 PostgreSQL 切换约定

切换由部署配置选择数据库 dialect，应用数据访问与业务逻辑不绑定具体数据库。SQLite 文件不能通过修改连接配置自动变成 PostgreSQL；已有实例切换数据库时，需要先执行经过验证的数据导出/导入步骤。首期实现中应为迁移预留一条受支持的数据搬迁命令或脚本，并验证用户、角色、授权、服务配置、密钥密文和审计记录能够搬迁。

SQLite 适合作为单机、自托管默认配置；需要多实例并发写入或集中式运维时，可部署 PostgreSQL。若未来需要利用 PostgreSQL 专属查询或高并发能力，必须先以明确的数据库能力决策更新本约定，并保留 SQLite 的支持边界说明。

## 实施周期估算

估算包含首期范围，不包含 A2A。假设有可持续投入的开发人员、首期不接企业 IdP，并包含自动化测试、基础部署文档和安全检查。

| 阶段 | 内容 | 估算 |
|---|---|---:|
| 技术验证与决策收敛 | MCP SDK 传输验证、双数据库接入验证、OpenAPI/cURL 和 Skills 解析边界确认、管理员首次登录与恢复方案 | 1 周 |
| 基础平台 | 项目骨架、数据库迁移、用户/API Key、平台管理员身份、角色与工具授权 | 2 周 |
| MCP 网关与审计 | 下游 MCP 注册、Streamable HTTP/SSE 连接、上游网关、工具过滤与调用二次授权、审计 | 2-3 周 |
| REST-to-MCP | 手动定义、OpenAPI/cURL 导入预览、REST 执行器和静态请求头配置 | 2-3 周 |
| 工作台与 Skills 广场 | 用户工作台接入资料、公开目录、来源管理和安装命令 | 1-2 周 |
| 集成与交付 | 双数据库回归、端到端测试、安全检查、Docker Compose 与运维文档 | 1-2 周 |

按两名工程师并行估算，首个可交付版本约 **9-12 个日历周**。一名全栈工程师顺序完成约 **16-22 周**。技术验证后，应根据导入范围、Skills 上游格式和实际团队投入重新估算。

## 开工前需要收敛的规格

- 管理员首次登录、凭证轮换与恢复流程。
- OpenAPI 文档的输入形式、`$ref` 支持范围、导入冲突和更新规则。
- cURL 导入的支持子集、预览与错误提示行为。
- Skills 展示字段、GitHub 来源刷新方式和安装命令格式。
- 静态下游密钥的加密密钥管理、目标 URL 的 SSRF 防护，以及审计记录保留周期。
